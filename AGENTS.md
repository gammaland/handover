# Working on handover.tools

Rules for anyone changing this repository: people and coding agents alike. `CLAUDE.md` imports this file.

## The order of work

1. **Spec first.** A change in behavior starts in `docs/spec/handoff.md` or `docs/spec/channel.md`. If the change is architectural (a new table, a new component, a new limit), update `docs/system-design.md` too.
2. **Then the code**, in `src/` (the Worker) or `client/` (the local channel client).
3. **Then the tests**, in `tests/`. Name each section after the spec section it checks, e.g. `(spec/channel §7.4)`.
4. **Add a `CHANGELOG.md` entry** if users or agents can notice the change. The newest entry goes first: `## YYYY-MM-DD · Title`, a `Tags:` line, a one-line summary, bullets, and an optional `For agents:` line. The same file is rendered at `/changelog`.
5. **Record the decision** in `docs/decisions.md` if you chose between real alternatives, rejected something, or learned something the hard way. Give it the next free `Dxx` number; code comments may cite it.

A spec that disagrees with the code is a bug in one of them. Write it down under "Known deviations" in the spec until it is fixed.

## Checks

```bash
scripts/check.sh      # repository rules (also runs in CI)
scripts/dev.sh        # local Worker on :8787, then in another shell:
tests/e2e.sh && tests/channel.sh && tests/quota.sh
```

All four must pass before a commit. CI runs them on Linux on every push.

## Rules

- **English only**, in code, comments, tests, docs and commit messages. `scripts/check.sh` rejects CJK text. Full-width Latin letters are allowed as test input.
- **No personal data.** No names, personal email addresses, home paths, hostnames, account IDs or tokens, in files or in commit messages. Credentials come from the environment (`CLOUDFLARE_API_TOKEN`), never from files in the repo.
- **Numbers in public copy come from code constants**, not from hand-typed text (D27). If a page states a limit or a retention period, derive it from the implementation. The privacy page (`/privacy`) must stay true: if you start keeping something new, or keep it longer, change the page in the same commit.
- **Don't break the channel protocol.** The SPAKE2 identities and the HKDF info strings (`percall-channel-*`) are protocol constants. Changing them needs a new protocol version.
- **Don't widen what the server can see.** `src/tools/channel.py` must never parse or decrypt ciphertext (D26). One-shot content is plaintext and the docs must keep saying so.
- **Nothing fetches on a GET of a code link** (D21, D38). Link previews must not burn a read-once handoff.
- **Use curl or requests in examples, not `urllib`**: Cloudflare's bot rules return 403 to its default User-Agent (D19).

## Layout

```
src/            the Worker: entry.py (routing, MCP), registry.py, guard.py, meter.py, tools/, website
client/         the channel client (embedded into the Worker at build time)
docs/           system design, specs, decisions
tests/          e2e.sh, channel.sh, quota.sh
scripts/        build.sh, dev.sh, deploy.sh, check.sh, block.sh
assets/         fonts and images, plus their generator scripts
```

`src/client_src.py`, `src/fonts_src.py` and `src/changelog_src.py` are generated by `scripts/build.sh`; never edit them.
